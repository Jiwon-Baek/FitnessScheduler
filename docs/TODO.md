# 26. 5. 7. Codex's 1st plan

## 목표 화면과 핵심 흐름

- iPad에서 바로 쓰기 좋은 HTML 기반 단일 페이지 웹앱으로 구현한다.
- 첫 화면은 좌측 회원목록, 우측 주간 시간표, 하단 작업 버튼으로 구성한다.
- 회원을 누르면 해당 회원의 가능한 시간을 선택하는 편집창을 띄운다.
- 운영시간 등록 버튼을 누르면 헬스장 휴무 시간을 선택하는 편집창을 띄운다.
- 시간표 칸을 누르면 그 시간에 가능한 회원 목록과 선택 버튼을 팝업으로 보여준다.
- 회원을 시간대에 배정하면 시간표 칸에 회원명이 표시되고, 회원목록에는 `월 11` 같은 배지가 붙는다.
- 스케줄 초기화는 확정 배정만 삭제하고, 회원 가능시간과 운영시간은 유지한다.
- 전체 정보 초기화는 확정 배정, 운영시간, 회원 가능시간, 회원목록 저장 상태를 모두 초기화한다.
- 이미지로 저장은 현재 시간표와 회원 배정 정보를 PNG 이미지로 내려받게 한다.

## 필요한 기술요소

- `index.html`: GitHub Pages에서 바로 열리는 앱 진입점.
- `style.js`: 색상 팔레트, iPad 대응 레이아웃, 버튼/모달/팝업/시간표 스타일 주입.
- `script.js`: 한국어 UI 문구, 회원/운영시간/가능시간/배정 상태 관리, 화면 렌더링, 저장/초기화/이미지 저장 로직.
- 브라우저 `localStorage`: 새로고침 후에도 회원, 운영시간, 가능시간, 배정 상태 유지.
- Pointer Events: iPad 터치 드래그로 운영시간/가능시간 범위 선택 지원.
- Canvas API: 외부 라이브러리 없이 현재 스케줄을 PNG로 저장.
- 반응형 CSS Grid: iPad 가로/세로 화면에서 회원목록과 시간표가 자연스럽게 재배치되도록 구성.
- GitHub Pages: 루트의 `index.html`을 기준으로 정적 호스팅.

## 구현관점에서 추가로 정해야 할 세부기능

- 실제 헬스장 운영 시간 범위: 현재 초안은 `10, 11, 12, 1, 2, ... 10` 형태로 표시한다.
- `1~10` 시간이 오전인지 오후인지 구분할지 여부: 예를 들어 `오후 1`, `오후 2`로 명확히 표시할 수 있다.
- 회원 정보 항목: 이름만 필수로 둘지, 전화번호/메모/수업권 잔여 횟수까지 둘지 정해야 한다.
- 한 시간대에 여러 명 배정 가능 여부: 현재 구현은 시간표 칸 하나당 회원 1명 배정을 기본으로 둔다.
- 한 회원을 같은 주에 몇 회까지 배정할지 제한 규칙이 필요한지 정해야 한다.
- 운영시간의 의미: 휴무 시간만 고르는 방식으로 둘지, 영업 가능 시간을 직접 고르는 방식으로 바꿀지 정해야 한다.
- 스케줄 충돌 규칙: 이미 배정된 회원이 다른 시간대에도 중복 배정될 수 있는지 정해야 한다.
- 이미지 저장 범위: 시간표만 저장할지, 회원목록 배지까지 함께 저장할지 정해야 한다.
- 데이터 백업 방식: 현재는 브라우저 저장소만 사용하므로, 장기적으로 CSV/JSON 내보내기와 불러오기를 추가할지 정해야 한다.
- 모바일 폰 지원 여부: 현재 우선순위는 iPad이며, 스마트폰은 최소 사용 가능 수준으로만 맞춘다.

- [전체 정보 초기화] 버튼을 누르면, 회원 가능시간 정보는 사라지는데, 회원의 명단은 유지된다. 회원의 명단은 오로지 추가 및 수동 삭제를 통해서만 이루어져야 한다.

- 이미지 저장 결과에 왼쪽 회원목록과 배지를 함께 그리며, 파일명에 `YYYYMMDD_HHMMSS` timestamp를 붙인다.
